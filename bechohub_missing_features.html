Bechohub: Core Architecture & Task Division

Omni-Channel Strategy (Web + Future Mobile App)

Architecting for Mobile & Web Simultaneously

Because the next product is a mobile app (React Native / Flutter), the Node.js backend must be treated as a pure, headless API from Day 1. We cannot rely on web-specific paradigms (like relying solely on HTTP-only cookies). We must implement strict API Versioning, Payload Optimization for slow mobile networks, and Device Agnostic Authentication. Below is the deep-tech breakdown of how tasks are divided to ensure the backend scales for both.

Architecture & DevOps Supratim (Senior)

1. API Versioning & Routing

Implementation: Move all routes under /api/v1/*. Mobile apps cannot be force-updated easily. If we change a schema in month 3, v1 must remain active for older app versions while the web moves to v2.
  • Router Refactor: Restructure `src/routes` to enforce versioning (`/v1/auth`, `/v1/products`).
  • Stateless Architecture: Ensure zero in-memory state in the Express app so it can scale horizontally across multiple instances (Render/AWS ECS) when mobile load hits.

2. Omni-Channel Authentication & Security

Implementation: Mobile apps rely on Bearer JWTs in the Authorization header. The auth middleware must robustly decode Supabase JWTs regardless of whether they come from a cookie (web) or header (mobile).
  • Advanced Rate Limiting: Implement `express-rate-limit` backed by Redis (or a DB table) using a composite key: `IP Address + Device ID / User ID`. Mobile apps can sometimes bug out and spam APIs; IP-only blocks will punish NAT users.
  • CORS & Helmet: Lock down CORS strictly to the Next.js frontend origin, but allow mobile app user-agents/origins via dynamic config. Implement `helmet` for header security.
  • Push Notification Schema: Expand Prisma schema with a `UserDevice` model to store FCM/APNs tokens for mobile push notifications later.

3. Database Optimization & Pagination

Implementation: Offset pagination (LIMIT/OFFSET) scales poorly on large tables and causes duplicate items in mobile infinite-scroll feeds if new items are added during scroll.
  • Cursor-Based Pagination: Implement cursor-based pagination in Prisma for the `products` and `inquiries` queries to ensure buttery smooth infinite scrolling on mobile.
  • Database Indexing: Review Prisma schema to ensure compound indices exist for common queries (e.g., `@@index([sellerId, status])`).

Implementation & Features Shinjan (Junior)

1. Payload-Optimized Controllers

Implementation: Mobile networks drop packets. Returning a 50KB JSON payload when the mobile app only needs 3 fields is an anti-pattern.
  • Sparse Fieldsets / DTOs: Write Express controllers that allow clients to specify what fields they need, or strictly enforce Data Transfer Objects (DTOs) that strip out unnecessary relational data before sending the response.
  • Inquiry & Lead Gen API: Build the CRUD routes for the new `Inquiry` model (Buyer asks Seller for a quote), ensuring the JSON response is minimal.

2. Advanced Image Processing (CDN Prep)

Implementation: Serving a 4MB 4K image to a mobile device will crash the app or eat data. Multer + Sharp must generate multiple variants.
  • Multi-Resolution Uploads: Configure Sharp middleware to take a seller's product image and generate three sizes: `thumbnail` (200x200), `mobile` (800x800), and `desktop` (1200x1200).
  • WebP Format: Force conversion of all uploaded images to `.webp` format in Sharp to reduce payload size by 30-50% for mobile clients.

3. Frontend & Dashboard Delivery

Implementation: Next.js frontend acting as the primary client while mobile is being developed.
  • Responsive Web UI: Build out the missing Seller Dashboard and RFQ/Inquiry modals in Next.js, ensuring they are perfectly responsive (since web mobile traffic will exist before the native app).
  • Deep Linking Prep: Ensure frontend routes (like `/product/123`) directly match the API entity IDs, so sharing links between mobile and web users works seamlessly.
  • Email Hooks: Wire up Resend/SendGrid for critical notifications (e.g., "New Inquiry Received") since push notifications won't exist until the mobile app launches.
The Omni-Channel Goal: By enforcing API versioning, cursor pagination, and multi-resolution images now, the backend will literally not need to be touched when the mobile development begins. It will be plug-and-play.
